# YOLO 训练结果图 · 怎么看、怎么分析

> YOLO 训练完自动生成 7 种图。每张图回答一个特定问题，放在一起就是模型的完整体检报告。

---

## 总览：7 张图各自的角色

| 图 | 文件名特征 | 回答什么问题 |
|------|------|------|
| **混淆矩阵** | `confusion_matrix_*.png` | 模型把什么东西认错了？ |
| **P 曲线** | `P_curve_*.png` | 不同置信度阈值下 precision 怎么变？ |
| **R 曲线** | `R_curve_*.png` | 不同置信度阈值下 recall 怎么变？ |
| **F1 曲线** | `F1_curve_*.png` | 什么阈值下 F1 最均衡？ |
| **PR 曲线** | `PR_curve_*.png` | 不考虑阈值，precision-recall 整体 tradeoff 如何？ |
| **标签分布** | `labels_*.jpg` | 标注的框有多大、在图的什么位置？ |
| **标签相关性** | `labels_correlogram_*.jpg` | 不同类别之间有没有标注耦合？ |

## 一、混淆矩阵（Confusion Matrix）

### 它长什么样

一个正方形表格，行 = 真实类别（Actual），列 = 预测类别（Predicted）。

对角线上的格子（左上到右下）是**预测对的**。非对角线的是**认错的**。

YOLO 还会多一列 **"background"**：模型觉得那里没东西（漏检）或者把背景当目标（误检）。

### 4 种单元格的含义

| 单元格 | 含义 | 好还是坏 |
|------|------|:--:|
| 对角线 | 真实类别 = 预测类别，认对了 | ✅ 越多越好 |
| 行内其他格 | 类别 A 被误认成类别 B | ❌ **看模式** |
| background 列 | 漏检：该有的目标模型没检测到 | ❌ FN |
| background 行 | 误检：模型在没东西的地方报了个框 | ❌ FP |

### 怎么读

1. **看对角线**：颜色深不深？数值大不大？对角线又亮又集中 = 分类准。
2. **看热区偏移**：某一行对角线之外有特别亮的格子 → 那两个类别容易被混淆。比如"猫"那行的"狗"列很亮 → 模型分不清猫和狗。
3. **看 background 列**：某一行 background 值大 → 这个类别漏检严重。提 imgsz 或者检查标注。
4. **看 background 行**：background 行值大 → 误检多。有可能是图像里背景物体被当成了目标，检查是否需要增加负样本。

![confusion_matrix](/media/029fbdea5341d4ec1b29586aef37a61ef9d13c42febad90821bb3470d1891a8d.png)

### 快速判断

| 模式 | 诊断 | 对策 |
|------|------|------|
| 对角线干净 | 分类没问题 | |
| 相邻两个类别互混 | 类间相似度高 | 增加这两个类别数据、或者合并类别 |
| background 列很亮 | 漏检多 | 提 imgsz、降 confidence、检查小目标标注 |
| background 行很亮 | 误检多 | 加负样本、提 confidence 阈值 |
| 全部挤在几个格子里 | 模型几乎没有分类能力 | 数据量太少或标注太差 |

## 二、P 曲线（Precision-Confidence Curve）

### 它长什么样

X 轴：置信度阈值（0 到 1）
Y 轴：Precision（精确率）

一条从左上到右下的曲线（通常）。阈值越高 → precision 越高（只保留最有把握的框），但 recall 越低。

$$
\text{Precision} = \frac{TP}{TP + FP}
$$

![P_curve](/media/b6afbc4a6f61095290b221704f6c6f1aa7bd4228a0b229f4ceae37b1ef94b390.png)

### 怎么读

- **曲线整体越高越好**：所有类别 precision 都接近 1.0 = 模型报的框几乎都是对的
- **曲线末尾不下垂最好**：阈值 0.9 时 precision 还很高 → 高置信度的框非常可靠
- **某条线特别低**：那个类别的误检多，模型经常把别的东西认成它

---

## 三、R 曲线（Recall-Confidence Curve）

![R_curve](/media/6094e7a2a475c1f824e85425ef6eef36c83fbcf867dd287602d0024f0f6d6160.png)

### 它长什么样

X 轴：置信度阈值
Y 轴：Recall（召回率）

一条从右上到左下的曲线。阈值越低 → recall 越高（框多），但 precision 越低。

$$
\text{Recall} = \frac{TP}{TP + FN}
$$

### 怎么读

- **曲线整体越高越好**：所有 recall 都在 0.8 以上 → 漏检少
- **阈值 0 时 recall 接近 1.0**：低阈值下模型能把大部分目标找出来
- **某条线特别低**：那个类别漏检严重 → 检查该类数据量和标注质量
- **和 P 曲线对读**：P 曲线的某个类别 precision 高但 R 曲线的 recall 低 → 模型对那个类别很保守（只敢报最有把握的，漏掉很多）

## 四、F1 曲线（F1-Confidence Curve）

![F1_curve](/media/d98b613d5093bcc78e2cbda60580379909ecbf49870ac0d185b1095ca05eb7f0.png)

### 它长什么样

X 轴：置信度阈值
Y 轴：F1 Score

一条倒 U 形曲线。中间某个阈值处有一个峰值。

$$
F1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}
$$

### 怎么读

- **峰值越高越好**：F1 的峰值 ≈ 该类的最佳综合表现
- **峰值对应的 X 轴位置**：就是该类的最佳置信度阈值。实际推理时用这个阈值。
- **峰值偏左**（低阈值时 F1 最高）：模型需要画很多框才能找到目标 → 偏向 recall
- **峰值偏右**（高阈值时 F1 最高）：模型只信高置信度 → 偏向 precision
- **F1 曲线平坦**：对阈值不敏感，模型输出置信度区分度不够

---

## 五、PR 曲线（Precision-Recall Curve）

![PR_curve](/media/960665f1ad72d48617ded45eb1eff244697a9c84bcda67211b32946c4fc89a41.png)

### 它长什么样

X 轴：Recall
Y 轴：Precision

一条从左到右逐渐下降的曲线。每个类别一条线。

### 这是最重要的一张图

PR 曲线下的面积就是 **AP（Average Precision）**。所有类别的 AP 取平均就是 **mAP@0.5**（用 IoU=0.5 时）或 **mAP@0.5:0.95**（IoU 从 0.5 到 0.95 十个值的平均）。

### 怎么读

- **曲线越靠右上角越好**：右上角 = 高 precision + 高 recall，理想情况
- **曲线下面积越大越好**：面积大 = AP 高 = 模型好
- **曲线开头在 precision=1.0 附近**：低 recall 时 precision 很高 → 模型对最有把握的框判断准确
- **曲线末尾掉得慢**：recall 接近 1.0 时 precision 还有一定水平 → 模型覆盖率高且不瞎报
- **某条线全在最下面**：那个类别基本没学好
- **基线（蓝色虚线）**：随机猜测的水平，曲线如果在基线以下那比瞎猜还差

### mAP 怎么从这张图算出来

- mAP@0.5：IoU 阈值设为 0.5 时，所有类别 AP 的平均值
- mAP@0.5:0.95：IoU 从 0.5, 0.55, 0.6...0.95 十个阈值的 AP 平均 → 更严格、更反映真实定位精度

## 六、标签分布图（labels）

![labels_distribution](/media/130a2aa484ce89a20accde1ac5f99e72f15ac53551e4b2fb507247a088a6d79e.png)

### 它长什么样

两张子图：
1. **左上**：每个类别的标注框数量（柱状图）
2. **右上**：框的中心点位置分布（热力图，反映目标在图像中经常在什么位置）
3. **左下**：框的宽度分布
4. **右下**：框的高度分布

### 怎么读

- **类别不均衡**：某个类别的柱子特别矮 → 数据太少，那类的 mAP 大概率低
- **中心点都挤在中间**：目标总是出现在画面中央 → 模型可能学不到边缘目标，加 mosaic 或 translate 增强
- **宽高分布集中在小值**：目标普遍偏小 → 提 imgsz，考虑加小目标增强
- **宽高分布集中在大值**：目标普遍偏大 → 降 imgsz 也行，重点查分类而非定位

## 七、标签相关性图（labels_correlogram）

![labels_correlogram](/media/a8cd83c163703c889b63be2bae39a7324c6a47ab064d205d99117fbf27c48002.png)

### 它长什么样

一个正方形矩阵，行和列都是类别名。每个格子的颜色代表两个类别的框在**同一张图**里共同出现的频率。

- 对角线当然是满的（自己和自己的相关性 = 1）
- 非对角线的深色格子 = 那两个类别经常一起出现在同一张图

### 怎么读

- **几乎全白（相关性低）**：各类别独立出现，没问题
- **某些格子很亮**：两个类别总是同框 → 如果模型把他们认混（从混淆矩阵能看到），可能是因为它们的环境高度重叠
- **一整行都很亮**：某个类别几乎总是和其他类别一起出现 → 这个类别的"独立"特征可能没学好

## 八、整体分析流程

拿到所有图后按这个顺序看：

```
1. 标签分布 → 数据有没有问题？
         ↓
2. 混淆矩阵 → 模型把什么认错了？
         ↓
3. PR 曲线 → mAP 是多少？哪个类最差？
         ↓
4. P/R/F1 曲线 → 最优置信度阈值在哪？
         ↓
5. 标签相关性 → 类别混淆的原因是不是同框？
```

### 三种典型的坏结果

| 表现 | 诊断 | 根因 |
|------|------|------|
| P 高 R 低，PR 曲线早早掉 | 太保守 | 模型只敢报有把握的，阈值调低有用但 precision 会掉 |
| R 高 P 低，PR 曲线开头就不高 | 太激进 | 模型乱报框，需要提阈值或增强 background 训练 |
| 混淆矩阵某两列互串 | 类间混淆 | 那两类太像，检查数据标注，考虑合并或增多两类数据 |
| mAP 还行但小目标差 | 分辨率不足 | 提 imgsz，关 mosaic（对小目标不友好），加 scale 增强 |

---

## 九、最优置信度阈值怎么选

1. 看 F1 曲线，找到每个类别的 F1 峰值对应的 X 轴位置 → 那就是那个类别的最优阈值
2. 如果只用一个全局阈值：取所有类别最优阈值的**中位数**或**按数据量加权平均**
3. 部署时 `conf=0.25`（默认）通常是 precision 和 recall 的折中
4. 需要高空框率 → 提 conf 到 0.5~0.7
5. 不能漏检 → 降 conf 到 0.1~0.15，配合 NMS 去重
